== Programmatic configuration

[source,kotlin]
----
val config = KebConfig(
    baseUrl = URI("https://example.test"),
    browser = KebBrowserName.CHROMIUM,
    headless = true,
    browserChannel = null,
    executablePath = null,
    remoteEndpoint = null,
    remoteConnectTimeout = 30.seconds,
    slowMotion = 250.milliseconds,
    actionTimeout = 10.seconds,
    navigationTimeout = 30.seconds,
    artifactsDirectory = Path.of("build/keb-artifacts"),
)
----

`KebBrowser.launch(config)` creates a reusable browser owner.
`browser.newSession()` creates an isolated context and page.

== JUnit annotation

[source,kotlin]
----
@KebTest(
    baseUrl = "https://example.test",
    browser = KebBrowserName.CHROMIUM,
    headless = true,
)
class BrowserTest
----

== Runtime properties

JVM system properties override annotation or programmatic defaults.

[cols="1,2"]
|===
|Property |Example

|`keb.baseUrl`
|`http://127.0.0.1:4173`

|`keb.browser`
|`chromium`, `firefox`, or `webkit`

|`keb.headless`
|`true` or `false`

|`keb.browserChannel`
|`chrome`, `msedge`, or another Playwright Chromium channel

|`keb.executablePath`
|`/opt/company/chrome/chrome`

|`keb.remoteEndpoint`
|`ws://playwright-server:3000/`

|`keb.remoteConnectTimeoutMillis`
|`30000`

|`keb.slowMoMillis`
|`250`

|`keb.actionTimeoutMillis`
|`10000`

|`keb.navigationTimeoutMillis`
|`30000`

|`keb.artifactsDirectory`
|`build/keb-artifacts`
|===

== Remote browser

Set `keb.remoteEndpoint` to connect with Playwright's native WebSocket protocol
instead of launching a browser in the test process:

[source,shell]
----
./gradlew test \
  -Dkeb.remoteEndpoint=ws://playwright-server:3000/ \
  -Dkeb.baseUrl=http://application:8080
----

Set `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` on remote-only test clients. The Java
driver is still required for the protocol connection, but no browser binary is
launched on that machine.

The client and server must use the same Playwright major and minor version.
Patch versions may differ, so the Java `1.62.0` client is compatible with the
`1.62.1` example server. The browser server controls its launch environment,
so `keb.headless`, `keb.browserChannel`, and `keb.executablePath` are
local-launch settings; channel and executable path are rejected when a remote
endpoint is configured. Closing `KebBrowser` closes its contexts and
disconnects without stopping the remote Playwright server.

In Kubernetes, expose the Playwright server with a ClusterIP Service and use
its WebSocket URL for `keb.remoteEndpoint`. The application URL must be
reachable from the browser pod, not merely from the test-runner pod.

Apply properties explicitly outside JUnit:

[source,kotlin]
----
val config = KebConfig.fromSystemProperties(
    KebConfig(baseUrl = URI("https://example.test")),
)
----

Invalid booleans, browser names, durations, and timeouts fail early with the
property name in the error.

== Gradle

Properties must reach the forked test JVM. The independent example forwards
both JVM and Gradle project properties, so either form works:

[source,shell]
----
./gradlew -p example :testing:test -Dkeb.headless=false
./gradlew -p example :testing:test -Pkeb.headless=false
----

Run a visible browser slowly enough to follow:

[source,shell]
----
./gradlew -p example :testing:test \
  -Dkeb.headless=false \
  -Dkeb.slowMoMillis=250
----

Consumer Gradle builds can forward the same values:

[source,kotlin]
----
tasks.test {
    val headless = providers.gradleProperty("keb.headless")
        .orElse(providers.systemProperty("keb.headless"))
    headless.orNull?.let { systemProperty("keb.headless", it) }
}
----

== Failure artifacts

The JUnit extension attempts to capture a full-page screenshot when a test
fails. The default directory is `build/keb-artifacts` and can be changed through
configuration or `keb.artifactsDirectory`.

== Threading

Playwright Java objects are not shared between arbitrary threads. A
`KebSession`, its context, and its page belong to one test execution. The JUnit
extension favors isolation and creates a fresh session for every test.

For browser installation behind a restricted corporate network, using an
approved local Chrome installation, and preparing offline build agents, see
link:corporate-network.adoc[Restricted Corporate Network Setup].
